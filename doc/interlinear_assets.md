# Full original-language assets

The bundled assets are generated from all six complete STEPBible source files
pinned to `b99716b0cddb648ddb95cc786a197180f2f97d48`. They are not generated from
the companion package's small test fixtures. The source lock, source header
notices, raw and decoded-text hashes, importer reports, transformation details,
and compressed-resource hashes travel with the assets.

| Dataset | Profile | Books | Chapters | Tokens | Compressed chapter bytes |
| --- | --- | ---: | ---: | ---: | ---: |
| `step-tahot-lqr` | `L+Q+R`, qere | 39 | 929 | 305,486 | 17,581,075 |
| `step-tagnt-n` | `N` | 27 | 260 | 137,646 | 7,190,200 |

Both dataset revisions are `0.1.0`; their reference system is `STEPBible-NRSV`.
The source revision, dataset revision, reading profile, and reference system are
separate concepts. The complete original-language assets occupy 25,485,995 bytes
before separately generated reference-mapping files: 24,771,275 compressed
chapter bytes plus manifests, attribution, source notices, lock, index, and
provenance. Uncompressed chapter JSON totals 285,082,773 bytes.

## Transport and runtime loading

`assets/interlinear/step-tahot-lqr` and `assets/interlinear/step-tagnt-n` each hold
a plain `manifest.json`, plain `attribution.json`, and gzip chapter resources in
`chapters/`. The manifest deliberately retains logical paths such as
`chapters/GEN.1.json`; the Flutter resource reader loads
`chapters/GEN.1.json.gz`, decompresses it, and returns those bytes to the package.
Manifest hashes apply to decompressed JSON. `provenance.json` additionally records
transport-byte hashes and sizes. Manifest and attribution resources are not gzip
encoded.

Gzip uses level 9, a zero timestamp, no stored filename, and the generic OS byte
255. Source JSON and ordering are unchanged. The generator verifies every
gzip round trip, then reads every staged chapter through
`JsonInterlinearDataSource` before finalizing the directory. The application can
read one chapter at a time and does not decompress a corpus at startup.

The original dataset generation used Dart 3.11.4 and produced identical
SHA-256 hashes for all 1,197 output files across two runs. The complete bundle
now also includes each registered edition mapping and its inventory/build provenance; its
regression checks reproducibility of every resulting file.

Flutter's asset registration must include the root metadata directory, both
dataset directories, and both `chapters/` directories. Directory asset entries
do not recursively register arbitrary nested directories.

## Coverage and reading-policy gaps

All 66 books and 1,189 source chapters have resources. There are 23,145 ordinary
TAHOT verse entries and 116 special entries, plus 7,918 TAGNT ordinary verse
entries. No fabricated empty positive verses are emitted.

TAHOT's main Leningrad/qere/restored profile covers every source verse group.
Fourteen individual ketiv positions have no spoken qere token; the importer
records these as informational omissions. `X` additions and inline apparatus
readings are excluded. Psalm verse-zero headings remain special entries.

TAGNT's `N` profile excludes 40 complete source verse groups. These include
John 7:53–8:11, Mark 16:9–20, and other variant-only entries. The exact addresses
are listed under `sourceEntriesWithoutSelectedTokens` in `asset-index.json` and
`provenance.json`. Seventeen edition-order warnings document ambiguous NA27
annotations that are preserved without applying guessed movements. This
profile is a STEPBible source-row reading, not a claim to reproduce NA27/NA28
exactly. A translation verse may consequently have no selected original tokens.
Translation correspondence is determined by the separate explicit mapping
data, not by assuming identical numbers are equivalent.

## Data ownership and regeneration

The source of these prepared files is now
[bible-io-interlinear-data](https://github.com/m0ty/bible-io-interlinear-data).
See its README for explicit source acquisition, standalone corpus generation,
Spanish supplement reproduction, and catalog sealing. Raw inputs are downloaded
separately and are not needed by consumers of prepared assets.

The Flutter app materializes a pinned build copy with
`python tool/fetch_interlinear_data.py`; it retains translation-specific mappings
and reseals them with
`dart run tool/generate_interlinear_bundle.dart --refresh-metadata --overwrite`.
No corpus is generated or downloaded during app startup.

Code licensing and data licensing remain separate. `THIRD_PARTY_NOTICES.md`
records the source's CC BY 4.0 attribution and component notices. Generation
preserves Unicode, supplied morphology and lexical identifiers, and source
reading order. Display spacing is reconstructed. No glosses, analyses, or
translation word alignments are generated by AI.
